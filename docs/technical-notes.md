# Технические заметки MultiKKT

Документ описывает технический контракт версии 11.3.19.0. Порядок действий оператора находится в [пользовательской инструкции](../INSTRUCTION_FOR_DUMMIES.md), а проверки на физическом стенде — в [полевом чек-листе](testing/2026-09-03-field-acceptance-full-contour.md).

## API ЕСМ

Приложение использует локальный HTTP API:

- `GET /api/v1/instances/info` — список экземпляров;
- `GET /api/v1/instances/info/{id}` — подробности экземпляра и `regData`;
- `GET /api/v1/dkktList` — физические ККТ, доступные через ДККТ;
- `POST /api/v1/tspiot` — добавление экземпляра;
- `PUT /api/v1/tspiot` — регистрация ККТ;
- `DELETE /api/v1/tspiot/{id}` — удаление выбранного экземпляра;
- `GET /api/v1/settings/{id}` — чтение конфигурации для диагностики;
- `PUT /api/v1/settings/lm/{id}` — привязка ККТ к контроллеру ЛМ ЧЗ;
- `GET /api/v2/info` — диагностика по отдельной команде оператора.

`PUT /api/v1/settings/{id}` не вызывается: полная перезапись неизвестной конфигурации слишком рискованна. При неожиданной структуре ответов `/instances/info` или `/dkktList` изменяющие запросы не выполняются.

Адрес ЕСМ по умолчанию — `http://127.0.0.1:51077`, `dkktPort` — `4042`. Порт `4041` относится к службе АТОЛ для ККМ и не используется как стандартный порт оркестра ДККТ.

## Экземпляры и порты

В автоматическом режиме программа выбирает один из двух существующих потоков:

- при активных сессиях одного ИНН регистрирует кассы через текущие сессии драйвера;
- без сессий или при разных ИНН последовательно открывает конкретные VCOM через Драйвер ККТ АТОЛ v.10.

Новые экземпляры получают первую свободную пару, начиная с `50401/51401`. Занятость любой стороны резервирует всю пару. Серийный номер ККТ должен содержать 14 ASCII-цифр, ФН — 16 ASCII-цифр; ИНН проверяется по длине, ASCII-цифрам и контрольным цифрам.

Массовая операция выполняет устройства последовательно, сохраняет успешные результаты при ошибке другой ККТ и останавливается после текущей безопасной операции. Ошибка контроллера или ЛМ не откатывает регистрацию.

## Контроллеры и ЛМ ЧЗ

На каждую ККТ приходится один прямой контроллер:

| Порядок | Служба | gRPC | REST |
| ---: | --- | ---: | ---: |
| 1 | `esm-lm-controller` | `50063` | `5063` |
| 2 | `esm-lm-controller-2` | `50064` | `5064` |
| 3 | `esm-lm-controller-3` | `50065` | `5065` |

Первый контроллер использует штатную службу. Для следующих создаются прямые SCM-клоны проверенного `lmcontroller.exe` с отдельными профилями и сертификатами. Постоянный supervisor или прокси KRS не создаётся.

На каждый ИНН приходится один ЛМ:

| Порядок ИНН | Службы | API | CouchDB |
| ---: | --- | ---: | ---: |
| 1 | `regime` / `yenisei` | `5995` | `5984` |
| 2 | `regime1` / `yenisei1` | `6995` | `7984` |
| 3 | `regime2` / `yenisei2` | `7995` | `8984` |

Базовый ЛМ, ранее установленный вендором, не переустанавливается: программа включает автозапуск и сохраняет прежний режим в manifest для возврата при удалении. Дополнительные ЛМ создаются из выбранного официального MSI с собственными ProductCode, каталогами, службами, cookie и правилом firewall только для API-порта.

Пакет проверяется по подписи ЦРПТ, `UpgradeCode` и структуре таблиц встроенного профиля. Точная версия, ProductCode или SHA-256 в программу не зашиты; выбранный файл фиксируется по имени, размеру, SHA-256 и отпечатку сертификата до конца операции. Подпись без совместимой структуры недостаточна.

Программа точечно обновляет только `settings.ldbControl` в `config_<serial>.yml`; `config-orchestrator.yml` не меняется. Запись привязки и диагностика — разные операции: отказ `PUT` означает непринятые настройки, а ответ `/api/v2/info` описывает текущее состояние и не меняет результат установки.

## Frontol

Источник базы — кассовый `%PROGRAMDATA%\ATOL\Frontol6\Settings\Frontol.ini`, секция `DATABASE`, текущее рабочее место `POS.NPOS`. Профили администратора и другие базы не перебираются. `isql.exe` берётся из штатной регистрации Firebird в Windows.

ККТ сопоставляются по COM-порту и физическому серийному номеру. В одной транзакции меняются только `ECRDEV.ESMHOST` и `ECRDEV.ESMPORT` для текущего рабочего места, после чего значения читаются повторно. `DEVICES.CONNECTIONSTRING`, COM-порт и прочие настройки драйвера не изменяются.

Перед записью создаётся JSON-снимок в `%LOCALAPPDATA%\EsmTspiotTool\frontol-backups`. Он предназначен для контролируемого восстановления тех же записей, содержит адрес базы и идентификаторы оборудования и не заменяет штатную резервную копию.

## Безопасность поставки

- приложение запрашивает права администратора манифестом при запуске;
- helper принимает только ограниченный протокол и не запускает произвольные команды, пути или аргументы;
- основной EXE проверяет точный набор файлов `Provisioner`, встроенные SHA-256, совпадение версий и метаданные KRS;
- соединение с helper проверяется по PID, SID и high integrity;
- удаляются только объекты с подтверждённым manifest владения KRS; изменённые после настройки YAML не перезаписываются;
- диагностика для копирования маскирует ИНН, номера ККТ, ФН, пути профиля Windows и типовые секреты;
- журналы хранятся в `%LOCALAPPDATA%\EsmTspiotTool\Logs` и очищаются через 14 дней.

Компактный ZIP не содержит Firebird, FMU-API, вендорный MSI, `lmcontroller.exe`, отдельный Erlang runtime, PDB, рабочие сертификаты, базы или журналы клиента.

## Сборка и проверка

Для разработки нужны .NET SDK 8 или новее и Visual Studio / Build Tools с MSBuild и средствами сборки .NET Framework 4.8.

Полная release-матрица, включая компактный ZIP:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_release_matrix.ps1
```

Матрица проверяет общий код под .NET 8 и .NET Framework 4.8, операторские тесты, Legacy и helper в режиме C# 5, Modern-сборку, LM safety, UI и контракт компактной поставки. Она не устанавливает MSI и не выполняет операции на физических ККТ.

Только Release-сборки используют MSBuild `PathMap`, заменяющий абсолютный путь рабочей копии на `/_/`. `scripts/verify_compact_security_contract.ps1` дополнительно отклоняет поставку, если собственный EXE или DLL KRS содержит абсолютный путь репозитория.

Компактный пакет можно собрать отдельно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package_compact_release.ps1
```

Результат создаётся в игнорируемом каталоге `artifacts/release`. ZIP содержит Legacy x86, общую DLL, helper с WiX DTF 4.0.6, инструкцию, полевой чек-лист, лицензию, уведомления и внутренние контрольные суммы. Внешний SHA-256 записывается рядом с ZIP.
