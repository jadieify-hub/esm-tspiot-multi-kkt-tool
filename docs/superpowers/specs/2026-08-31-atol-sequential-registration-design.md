# Автоматическая поочерёдная регистрация ККТ АТОЛ

## Контекст

ЕСМ 1.6.3.2 отклоняет `PUT /api/v1/tspiot` с ошибкой 1026, если
`/api/v1/dkktList` одновременно содержит ККТ разных ИНН. Уже
зарегистрированные ККТ разных ИНН после регистрации работают вместе. Полевой
сценарий оператора — поочерёдно включать связь с каждой ККТ в «Тесте драйвера
ККТ» — подтверждён.

Пробник на драйвере АТОЛ 10.10.8.24 подтвердил:

- штатный API ДТО открывает конкретную ККТ по VCOM без UI;
- после открытия `MI_00`-порта ККТ появляется в `dkktList`, после закрытия
  исчезает;
- `USB:auto` непригоден для нескольких ККТ, потому что выбирает первое
  устройство;
- серийный номер читается сразу после открытия и позволяет проверить
  соответствие VCOM физической кассе.

## Цель

Автоматический режим сам управляет штатными сессиями драйвера АТОЛ: открывает
ровно одну физическую ККТ, регистрирует её в ЕСМ, закрывает соединение, создаёт
локальный комплект и переходит к следующей ККТ. Подмена ответов ЕСМ, фильтрация
`dkktList`, прокси и управление интерфейсом «Теста драйвера» запрещены.

## Выбранная архитектура

1. Приложение сначала выполняет обычное read-only обнаружение ЕСМ.
   Если видимые ККТ имеют один ИНН либо все уже зарегистрированы, существующий
   поток сохраняется без новых окон.
2. Если `dkktList` пуст либо содержит незарегистрированные ККТ разных ИНН,
   включается VCOM-конвейер.
3. Перед VCOM-конвейером приложение закрывает все собственные сессии и несколько
   раз читает `dkktList`. Оставшиеся строки считаются чужими сессиями. Программа
   не завершает чужие процессы: оператор получает список касс и предложение
   закрыть Frontol, «Тест драйвера ККТ» или другое удерживающее ПО, после чего
   может повторить проверку.
4. Порты перечисляются из системной ветки устройств Windows. Берутся только
   устройства АТОЛ с интерфейсом `MI_00`; `MI_02` и `USB:auto` не используются.
5. Для каждого порта приложение динамически загружает установленный API ДТО,
   открывает COM-порт, читает модель, версию и серийный номер, затем получает из
   реального `dkktList` полную строку с ФН и ИНН. После снимка порт закрывается.
6. Перед каждым POST/PUT снова открывается только сопоставленный VCOM и
   проверяется, что `dkktList` содержит ровно целевую ККТ. Только после этой
   проверки разрешено изменение ЕСМ.
7. После успешного PUT выполняется опрос
   `GET /api/v1/instances/info/{serial}` раз в две секунды до 60 секунд. Успех —
   только состояние «Зарегистрирован» и совпадающие после `Trim` серийник, ФН и
   ИНН.
8. VCOM закрывается в `finally` до запуска привилегированного helper. Установка
   ЛМ ЧЗ и контроллера использует только локальные файлы, адреса, порты,
   серийник и ИНН; физическая сессия ККТ ей не нужна.
9. Привязка выполняется существующим
   `PUT /api/v1/settings/lm/{id}` с последующим read-back. Рабочий эндпоинт не
   меняется.
10. После успешной обработки всех строк приложение временно открывает все
    сопоставленные VCOM, подтверждает полный состав `dkktList` без изменяющих
    запросов и закрывает все сессии в обратном порядке. Финальный read-back ЕСМ
    выполняется по всем ККТ.

## Граница поставки и разрядность

- Вендорные DLL не входят в репозиторий и компактный ZIP.
- API ДТО загружается только операторским EXE из установленного каталога АТОЛ.
- Путь берётся из uninstall-записи драйвера с безопасными fallback-каталогами;
  разрядность `fptr10.dll` должна совпадать с процессом.
- Компактный Legacy EXE собирается x86 для установленного 32-битного ДТО.
  Modern использует DLL своей RID-разрядности и выдаёт понятную ошибку, если
  подходящего драйвера нет.
- Helper, IPC, профили служб и состав компактного ZIP не получают API или DLL
  АТОЛ.

## Ошибки и отмена

- Не найден VCOM `MI_00`, неподдерживаемая прошивка, несовпадение серийника,
  занятый порт, чужая сессия и таймаут подтверждения имеют отдельные сообщения.
- Отмена прекращает новые изменения, закрывает текущую и все временно открытые
  сессии. Уже зарегистрированные ККТ и созданные комплекты не откатываются.
- Каждый open/close, каждый опрос `dkktList`, видимые ИНН и количество ККТ
  записываются в журнал через существующее маскирование.
- Для TCP, чистого RS-232 и неподдерживаемых USB-конфигураций остаются ручные
  вкладки; автоматический режим честно объясняет ограничение.

## Приёмка

- `204 No Content` от `dkktList` трактуется как пустой список; `200` с пустым или
  повреждённым телом остаётся ошибкой контракта.
- Одно-ИНН поток и поток «все уже зарегистрированы» не показывают новых окон.
- При разных ИНН каждая мутация выполняется только при единственной целевой ККТ
  в `dkktList`.
- После PUT проверяется фактическое зарегистрированное состояние, а не только
  HTTP-успех.
- Сессия ККТ закрыта до создания ЛМ/контроллера.
- Ошибка в середине и отмена закрывают все принадлежащие приложению сессии и не
  откатывают ранее завершённые строки.
- Shared net8/net48, operator adapter net8/net48, helper, Legacy C# 5, Modern,
  UI/safety-гейты и компактный ZIP проходят; ZIP по-прежнему содержит 7 файлов.
