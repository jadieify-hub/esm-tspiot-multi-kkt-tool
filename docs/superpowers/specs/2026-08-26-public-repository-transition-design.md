# Перевод репозитория в публичный режим

## Цель

Подготовить `jadieify-hub/esm-tspiot-multi-kkt-tool` к публичному доступу без публикации устаревших небезопасных сборок, противоречивой документации или локальных промежуточных артефактов.

Публичность включается только после завершения очистки, коммита, push и успешного CI. Тег `v11.1` остаётся на коммите `82c90b5` и больше не перемещается.

## Подтверждённое исходное состояние

- `main`, `origin/main` и тег `v11.1` указывают на `82c90b5`.
- Тег `v11.1` содержит freeware-лицензию KRS; GitHub определяет пользовательскую лицензию как `Other`.
- Релиз `v11.1` содержит четыре проверенных файла: компактный EXE, Markdown-инструкцию, PDF-инструкцию и SHA-256.
- Аудит текущих файлов и доступной Git-истории не обнаружил секретов, реальных пользовательских данных, локальных путей или крупных бинарников.
- Найденные значения паролей, токенов, ИНН, номеров ККТ и ФН находятся в тестовых фикстурах и не являются рабочими данными.
- Старый GitHub Release `v11` содержит сборки до закалки безопасности, включая две автономные Modern-сборки размером около 60 МБ.

## Изменения в репозитории

1. README уточняется: `artifacts/release` — локальная игнорируемая Git папка, а опубликованные файлы находятся в GitHub Releases.
2. В README добавляется бейдж текущего GitHub Actions workflow `CI`.
3. `RELEASE_NOTES_v11.1.md` синхронизируется с авторитетным телом GitHub Release:
   - добавляется прохождение 72 тестов в .NET 8 через CI;
   - добавляется раздел о freeware-лицензии со ссылкой на `LICENSE` в теге `v11.1`.
4. LICENSE и права пользователя не меняются.

Документация фиксируется отдельным cleanup-коммитом и отправляется в `origin/main`. Тег `v11.1` не перемещается из-за документационных изменений после выпуска.

## Очистка релизов и локальных артефактов

GitHub Release `v11` удаляется полностью. Тег `v11` и соответствующая Git-история сохраняются. Удаление релиза окончательно удалит опубликованные ассеты, включая две Modern-сборки; их можно будет получить только повторной сборкой исходников тега `v11`.

Это осознанное решение: старые исполняемые файлы были собраны до исправлений аварийного PowerShell-сценария и других защитных доработок, поэтому они не должны оставаться доступными из публичного репозитория.

Из локальной игнорируемой папки удаляются только два неоднозначных файла:

- `artifacts/release/MultiKKT-ESM-TSPioT-v11.exe`;
- `artifacts/release/SHA256SUMS-v11.txt`.

Остальные локальные исторические файлы не затрагиваются.

## Синхронизация GitHub Release v11.1

После push tracked-файл `RELEASE_NOTES_v11.1.md` используется для обновления тела GitHub Release `v11.1`. Ассеты, их имена, размеры и контрольные суммы не изменяются. Релиз остаётся стабильным и помеченным `Latest`.

## Проверка перед публикацией

До изменения видимости должны быть подтверждены:

- чистая рабочая копия и совпадение `main` с `origin/main`;
- успешный CI для cleanup-коммита;
- прохождение тестов .NET 8 и .NET Framework и сборка Legacy/Modern в CI;
- отсутствие GitHub Release `v11` при сохранённом теге `v11`;
- наличие четырёх неизменённых ассетов `v11.1` и совпадение SHA-256;
- неизменность тега `v11.1` на `82c90b5`;
- корректный текст README и тела релиза `v11.1`.

## Публичные настройки

После успешной проверки репозиторий переводится из `private` в `public`. Затем:

- добавляются тематические метки `windows`, `winforms`, `dotnet`, `kkt`, `fiscal-register`, `atol`, `piot`;
- поле Website в About указывает на `https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/releases/latest`;
- проверяются автоматическое secret scanning и включённая push protection;
- подтверждается отображение лицензии как `Other`;
- без авторизации открываются главная страница, README и Latest Release.

Классическая защита ветки `main` не включается: текущий рабочий процесс владельца использует прямые проверенные push в `main`. Это решение можно пересмотреть отдельно.

## Риски и необратимость

- Удалённые ассеты `v11` нельзя восстановить без повторной сборки.
- Видимость репозитория можно вернуть в private, но уже полученные внешними пользователями копии отозвать невозможно.
- История Git не переписывается, теги `v11` и `v11.1` сохраняются.
- Если любой этап проверки не пройден, изменение видимости не выполняется.
