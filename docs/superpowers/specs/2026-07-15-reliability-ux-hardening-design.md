# Усиление надежности и интерфейса ЕСМ/ТС ПИоТ

> Историческая спецификация укрепления исходного массового режима. Его текущая сквозная оркестрация с контроллерами ЛМ ЧЗ определена в `2026-08-26-multi-inn-lm-gateways-design.md`.

## Цель

Устранить риски массовой регистрации, повысить диагностируемость и сделать форму пригодной для рабочих областей 800x600 без изменения контрактов четырех существующих пошаговых кнопок.

## Надежность API

- Разбирать только ожидаемые структуры `instances[]`, `kkt[]` и детальный ответ экземпляра; корректный JSON неправильной формы считать ошибкой контракта.
- Добавить `GET /api/v1/instances/info/{id}` и read-only `GET /api/v1/settings/{id}`.
- Не выполнять автоматический `PUT /settings/{id}`: настройки только журналируются для диагностики.
- Покрыть методы, URL и JSON-тела GET/POST/PUT контрактными тестами через поддельный `HttpMessageHandler`.
- Добавить `CancellationToken` во все API-методы; сохранить старые перегрузки для существующих кнопок.
- Адрес, отличный от loopback (`127.0.0.1`, `localhost`, `::1`), считать предупреждением с явным подтверждением.
- Серийники, ИНН и порты принимают только ASCII-цифры.

## Массовая регистрация

- Вынести выполнение из `MainForm` в `BulkRegistrationWorkflow`.
- Новые ККТ получают свободные пары `50401/51401`, далее +1; занятый один порт резервирует всю пару.
- Существующий экземпляр не всегда пропускается: workflow запрашивает детали. Наличие полного `regData` означает «уже зарегистрирован», отсутствие `regData` — «создан, требуется PUT».
- После успешного POST workflow ожидает готовность экземпляра ограниченное время и повторяет транзитные ошибки `1013` не более трех раз с небольшой задержкой.
- Ошибка одной ККТ не прерывает остальные.
- Отмена прекращает новые запросы, но не откатывает уже выполненные операции.
- Прогресс сообщает номер ККТ, общее количество и текущий этап.
- Ошибки `1012/1013` собираются в итог; автоматический запуск PowerShell из массового сценария не выполняется.

## Интерфейс

- Заголовок формы отражает управление ККТ, а не только добавление второй.
- Размер формы ограничивается `Screen.WorkingArea`; минимальный целевой размер внешнего окна — не более 760x540.
- Корневая область допускает вертикальную прокрутку, журнал занимает оставшуюся высоту.
- Подтверждение массовой операции — отдельный прокручиваемый диалог с таблицей, а не MessageBox.
- Во время выполнения отображаются статус и кнопка отмены.
- Блок восстановления службы остается скрытым до ошибки и не должен выталкивать журнал за экран.
- Порты получают понятные подписи с сохранением технических имен `port`, `softPort`, `dkktPort`.

## Журнал

- Видимый журнал остается редактируемым по просьбе пользователя.
- Каждая запись дополнительно сохраняется в файл `%LOCALAPPDATA%\EsmTspiotTool\Logs`.
- Добавляется команда копирования маскированной диагностики: ИНН, ФН и серийники частично скрываются.
- Ошибка записи файла не должна блокировать основную операцию и фиксируется только в видимом журнале один раз.

## Совместимость и поставка

- Не добавлять внешние runtime-зависимости в общую библиотеку.
- Legacy EXE остается AnyCPU/.NET Framework для Windows 7 SP1-11 и не называется self-contained.
- Modern-проекты остаются self-contained для поддерживаемых Windows 10/11, отдельно x86 и x64.
- README и инструкция явно описывают различия вариантов.

## Проверка

- Все существующие тесты проходят.
- Новые тесты покрывают строгую форму JSON, HTTP-контракты, loopback-предупреждение, ASCII-цифры, возобновление PUT и продолжение после ошибки.
- Legacy EXE компилируется системным `csc.exe` без предупреждений.
- UI Automation находит четыре старые кнопки, массовую кнопку, статус, отмену и копирование диагностики.
- Окно запускается внутри рабочей области 800x600.
