# FMU-API и настройка Frontol

История реализации 11.3.16.0, не текущая инструкция. С 11.3.17.0 Frontol настраивается отдельной кнопкой, а финальная проверка готовности ЛМ убрана. Актуальные сценарии: [инструкция оператора](../../../INSTRUCTION_FOR_DUMMIES.md) и [указатель документации](../../README.md).

Согласованный объём: две независимые опции в существующей программе, по умолчанию выключены. Отдельный форк не нужен.

## План реализации

- [x] FMU-API: добавить режим в общий координатор и страницу ЛМ ЧЗ. Сохранить регистрацию ККТ и установку ЛМ по ИНН; не вызывать создание контроллеров, привязку и проверку привязки ЕСМ. Результаты и ручные этапы должны явно показывать неприменимость этих действий. Существующие контроллеры не удалять и не останавливать.
- [x] Frontol: подтвердить порт и применение настроек; читать единственный Frontol.ini из ProgramData. Сопоставлять POS.NPOS с RMK.CODE, затем ККТ по ComFile и проверенному серийному номеру. Менять только ECRDEV.ESMHOST/ESMPORT в одной транзакции с проверкой прежних значений, сохранять данные для отката. Не менять CONNECTIONSTRING и не использовать FrontolAdmin.ini.
- [x] Интерфейс: добавить обе опции в автоматическую настройку; использовать тот же режим на вкладке ЛМ ЧЗ. Настройка Frontol — заключительный этап; неоднозначное сопоставление или ошибка не должны отображаться как успех.
- [x] Проверка: существующие консольные тесты плюс минимальные проверки режима FMU, разбора INI/COM и безопасного сопоставления. Проверить обе сборки Windows, локальную базу без сохранения тестовых изменений, интерфейс и итоговый diff. Обновить README с ограничениями и порядком применения.

## Ограничения

Сохраняются .NET Framework 4.8 и .NET 8, x86 и текущие инструменты тестирования. Не устанавливать и не запускать FMU-API автоматически. Бизнес-инициализация ЛМ остаётся отдельной процедурой. Не завершать Frontol принудительно. Не менять реальные службы и кассы при тестировании.

## Результат проверки

- `scripts/run_release_matrix.ps1`: RELEASE_MATRIX_OK, включая обе платформы тестов, C# 5, интерфейс, Modern и компактную поставку 11.3.16.0.
- `dotnet run --project tests/EsmTspiot.Operator.Tests -c Release -f net8.0-windows -- --frontol-rollback-check` (также `-f net48`): запись, восстановление, конфликт и устаревший снимок проверены через установленный Firebird 2.1 на двух тестовых ККТ; всё завершено ROLLBACK. Нативный `isql -i` читает временный SQL без BOM/пароля, учётные данные передаются только через окружение дочернего процесса. Это устраняет различие stdin в .NET Framework и .NET 8.
- Независимое ревью: замечания по отмене и подтверждению регистрации закрыты. README, снимок интерфейса и полевая памятка обновлены.
- Полный сценарий с физическими ККТ, продажей и офлайн-проверкой марки не выполнялся. Клиент Firebird и FMU-API в поставку не включены. GitHub Releases не изменялись.
