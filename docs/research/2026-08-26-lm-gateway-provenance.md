# Происхождение контракта привязки ЕСМ к ЛМ ЧЗ

**План составлен:** 2026-08-26

**Публичный источник повторно проверен:** 2026-08-27

**Область:** только HTTP-контракт привязки уже зарегистрированного экземпляра ЕСМ к уже готовому контроллеру ЛМ ЧЗ. Создание и конфигурация Windows-служб сюда не входят.

## Подтвержденный внешний контракт

| Факт | Официальный публичный источник | Внутреннее имя проекта |
| --- | --- | --- |
| Метод и путь: `PUT /api/v1/settings/lm/{id}` | CSI, раздел «Настройка ЕСМ», шаг 6 | `TspiotDefaults.LmSettingsPath`, `ConfigureLmGatewayAsync` |
| `id` обозначает идентификатор экземпляра ЕСМ; в описанном процессе он задается равным `kktSerial` | CSI, раздел «Настройка ЕСМ», шаги 3–6 | `InstanceId`, `KktSerial` |
| JSON-поле `address` имеет тип string | CSI, пример тела PUT | `LmConnectionRequest.Address` |
| JSON-поле `port` имеет числовой тип | CSI, пример тела PUT | `LmConnectionRequest.Port`, `ControllerGrpcPort` после отдельного compatibility gate |
| JSON-поля `login` и `password` имеют строковый тип | CSI, пример тела PUT | только короткоживущие credentials непосредственно перед PUT |

Источник: [«SetRetail10 — Установка и настройка ТС ПИоТ»](https://crystals.atlassian.net/wiki/spaces/SR10SUPPORT/pages/6404898850/SetRetail10), публичный портал поддержки продуктов CSI.

Смысл `address` и `port` в официальном шаге — адрес и порт сервера ЛМ ЧЗ с контроллером ЛМ, к которому настраивается связь ЕСМ. Имя `ControllerGrpcPort` является термином этой реализации; фактический тип слушателя и его совместимость должны быть отдельно подтверждены процедурой service-provisioning, а не выводиться только из примера порта.

Официальный пример использует имя заголовка `ContentType`. Реализация отправляет стандартный HTTP-заголовок `Content-Type: application/json; charset=utf-8`; это транспортное исправление синтаксиса примера, а не дополнительное vendor-specific поле.

## Что публичный источник не подтверждает

Проверенная инструкция **не подтверждает**:

- API удаления или очистки LM-настройки экземпляра ЕСМ;
- безопасную повторяемость PUT после timeout, разрыва соединения или потерянного HTTP-ответа;
- read-back, который доказывает фактическое применение настроек после ответа 2xx;
- создание нескольких Windows-служб контроллера ЛМ;
- отдельный data/config path, второй локальный порт, формат профиля, service account, dependencies или recovery actions;
- возможность копировать штатный профиль, секреты, сертификаты или другие данные официальной службы.

Поэтому успешный HTTP-ответ называется `BindingAccepted`, а не `Verified`. Потерянный ответ не повторяется автоматически и требует состояния `RequiresAttention`. Служебные и профильные факты могут появиться в публичном коде только после отдельного `PublicSourceReady` из второго плана.

## Граница независимой реализации

Архив стороннего ПО `RollingPinForESM.zip` не является источником имен, кода, пользовательского интерфейса, сценариев, формата конфигурации или служебных параметров этого проекта. Его содержимое повторно не исследуется.

Разрешенные основания реализации:

1. официальный публичный HTTP-контракт CSI, указанный выше;
2. публичные стандарты HTTP, JSON и Windows API;
3. самостоятельно спроектированные модели и имена `LmGateway*`;
4. для будущих служб — только процедура compatibility/publication gate второго плана.

В журнал не включаются реальные `login`, `password`, ИНН, серийные номера, адреса организации или иные эксплуатационные данные.
