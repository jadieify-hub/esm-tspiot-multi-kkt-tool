# Compatibility gate официального контроллера ЛМ ЧЗ

**Дата проверки:** 2026-08-27

**Режим репозитория:** private

**Технический gate:** `TechnicalCompatibilityReady`

**Публикационный gate:** `PublicSourcePending`

**Целевая версия:** `1.6.3.2`

## Решение

Техническая совместимость и право на публикацию — разные проверки.

- `TechnicalCompatibilityGate` разрешает исследование в одноразовой Windows Sandbox и частную реализацию только после воспроизводимого доказательства изоляции.
- `PublicationGate` не блокирует частное исследование, но блокирует перевод ветки/репозитория в public и публикацию сборки с недокументированными vendor-specific фактами.
- Отсутствие ответа правообладателя больше не блокирует VM-характеризацию. Оно остаётся причиной не публиковать недокументированную часть.

Для версии `1.6.3.2` выбран один production-режим: собственная Windows-служба-супервизор запускает проверенный официальный бинарный файл дочерним процессом и задаёт отдельный корень `ProgramData` только в environment block этого процесса. Machine-wide environment, SCM-registry environment, junction, hard link, копия или патч vendor binary не используются.

Пользовательские аргументы не принимаются, а для иной версии режим должен быть подтверждён отдельно.

## Результат технической характеризации

Исследование выполнено в одноразовых Windows Sandbox без производственных ККТ, ИНН, учётных данных и доступа к сети организации. Два полных чистых прогона и один отдельный контроль пустого профиля дали одинаковые выводы:

1. Штатная установка создаёт одну службу и один machine-wide профиль.
2. Самодокументируемый CLI не предоставляет аргумент пути к данным; неизвестные аргументы отклоняются.
3. Контроллер выводит корень профиля именно из process-local переменной `ProgramData`; изменение `ALLUSERSPROFILE` результата не даёт.
4. Два дочерних процесса с разными `ProgramData` одновременно открывают независимые пары локальных портов и обращаются к разным целевым LM endpoint.
5. Пустому профилю достаточно минимальной конфигурации: CA и серверные ключи/сертификаты контроллер создаёт сам. Хэши сгенерированных ключевых артефактов различаются между профилями и прогонами; копирование штатных секретов не требуется и запрещено.
6. Listener PID принадлежит непосредственно проверенному дочернему процессу; супервизор может проверять parent/child relationship и точные порты.

Кандидаты проверены от наименее рискованного к более рискованному:

1. официальный аргумент отдельного data/config directory — отсутствует;
2. отдельный рабочий/исполняемый путь без reparse point — не решает фиксированный machine-wide профиль;
3. app-owned supervisor с отдельным process-local `ProgramData` — **PASS**;
4. junction не потребовался и в production запрещён.

Production-контракт фиксирует только точное имя environment key из capability profile; путь выводится программой из идентификатора управляемой службы. UI, manifest и IPC не могут передать произвольную переменную окружения или командную строку. Супервизор обязан работать с restricted service SID, а дочерний процесс — наследовать ограниченный токен; межпрофильный доступ и корректное завершение отдельно входят в интеграционные критерии реализации.

## Условия `TechnicalCompatibilityReady`

Технический gate проходит только если:

- два дополнительных экземпляра работают одновременно на разных портах;
- изменение одного профиля не меняет второй;
- служба, процесс и listener PID сопоставляются однозначно;
- удаление одного экземпляра не затрагивает остальные;
- установщик и рабочий бинарный файл имеют ожидаемые hash, version и signer;
- после выбора нового `esm-lm-controller_*-windows-setup.exe` все существующие экземпляры переходят в `VersionVerificationPending` и не запускаются до повторной проверки/пересоздания версионнозависимых артефактов.

Vendor-совместимость этих инвариантов подтверждена для `1.6.3.2`. Безопасность restricted service SID, недоступность чужого профиля, graceful stop и полный remove/cleanup остаются обязательными acceptance tests реализации; их не разрешается заменять process kill или общим `LocalSystem`-доступом.

Поддержка иной версии требует нового capability profile и повторной характеризации. При неизвестной версии создание/запуск блокируются, а просмотр, удаление принадлежащих приложению артефактов и ручная привязка ЕСМ остаются доступны.

## PublicationGate

Официальные публичные инструкции подтверждают обычную интерактивную установку одного контроллера и порт `50063`, но не описывают multi-instance, схему профиля и SCM-параметры. Поэтому `PublicSourcePending` сохраняется.

Перед будущим переводом этой ветки, репозитория или релиза в public нужно отдельно проверить основание публикации для:

- механизма изоляции и путей;
- минимальной схемы профиля;
- service account, dependencies, start mode и recovery actions;
- любых vendor-specific литералов в source, tests, docs и compiled builds.

До этого рабочая ветка и её сборки остаются частными. Этот gate не считается технической гарантией и не заменяет консультацию с юристом.

## Граница независимой реализации

`RollingPinForESM.zip` может использоваться только как внешнее подтверждение самого бизнес-сценария. Из него не переносятся код, имена функций, UI, команды, схема конфигурации, патчи или тексты. Все внутренние имена проекта остаются в семействе `LmGateway*`.
