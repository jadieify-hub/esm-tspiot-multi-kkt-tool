# Мульти-ККТ в ЕСМ/ТС ПИоТ

[![CI](https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/actions/workflows/ci.yml/badge.svg)](https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/actions/workflows/ci.yml)

WinForms-приложение работает с локальным HTTP API ЕСМ/ТС ПИоТ. Оно показывает созданные экземпляры и занятые порты, последовательно подключает вторую, третью и следующие ККТ, содержит массовый режим и безопасно удаляет дополнительные экземпляры. Для ККТ с разными ИНН программа создаёт отдельные службы официального контроллера ЛМ ЧЗ, изолирует их профили и привязывает каждую ККТ к её адресу ЛМ.

Программа не меняет настройки драйвера АТОЛ. В ручном сценарии пользователь обязан проверить связь именно с нужной физической ККТ.

Для управления Windows-службами архив распаковывает администратор в `C:\Program Files\KRS\MultiKKT`. Из Downloads, Desktop и других доступных на запись папок создание, обновление и удаление служб намеренно отключено; просмотр и ручная привязка к ЕСМ остаются доступными.

## Реализованные запросы ЕСМ

- `GET /api/v1/instances/info` - список экземпляров.
- `GET /api/v1/instances/info/{id}` - подробности экземпляра и `regData`.
- `GET /api/v1/dkktList` - физические ККТ, доступные через ДККТ.
- `POST /api/v1/tspiot` - добавление экземпляра.
- `PUT /api/v1/tspiot` - регистрация ККТ.
- `DELETE /api/v1/tspiot/{id}` - удаление дополнительного экземпляра.
- `GET /api/v1/settings/{id}` - чтение конфигурации для диагностики.
- `PUT /api/v1/settings/lm/{id}` - привязка зарегистрированной ККТ к готовому контроллеру ЛМ ЧЗ.

`PUT /api/v1/settings/{id}` намеренно не вызывается: автоматическая перезапись неизвестной конфигурации слишком рискованна.

## Надежность и безопасность

- Ответы `/instances/info` и `/dkktList` проверяются по ожидаемой JSON-структуре. При неожиданном ответе изменяющие запросы не выполняются.
- ИНН проверяется по длине, ASCII-цифрам и контрольным цифрам.
- Серийный номер ККТ должен содержать 14 ASCII-цифр, ФН - 16 ASCII-цифр.
- Нетипичные префиксы ККТ и ФН дают предупреждение, но не блокируют работу.
- Порты проверяются на диапазон и различие, включая запрет совпадения `port` или `softPort` с `dkktPort`.
- В ручном режиме отображаются все созданные экземпляры ЕСМ и занятые ими порты. Свободная пара рассчитывается по фактическому списку; одна занятая сторона резервирует всю пару.
- Адрес не на loopback-интерфейсе вызывает предупреждение перед продолжением.
- Массовая операция выполняет устройства последовательно, продолжает работу после ошибки одной ККТ и поддерживает остановку с сохранением уже полученных результатов.
- Привязки к контроллерам ЛМ также выполняются последовательно. Один локальный endpoint нельзя назначить нескольким ККТ; потерянный ответ не повторяется автоматически и помечается как требующий ручной проверки.
- Логины и пароли ЛМ ЧЗ существуют только в памяти текущего сеанса, не входят в план и очищаются после попытки привязки. Пароль не показывается в таблице и маскируется на границах журнала.
- Привилегированный helper не принимает произвольные команды, пути или секреты; имена служб, профили и пути выводятся из 14-значного серийного номера ККТ.
- Поддержка контроллера привязана к проверенному capability-профилю версии `1.6.3.2`. Другая версия не устанавливается «наугад»: для неё нужна отдельная проверка и обновление программы.
- Удаляются только службы с полностью подтверждённой меткой владения KRS. Профиль, сертификаты, логи и метаданные этого экземпляра очищаются автоматически; при `CleanupPending` есть кнопка `Повторить очистку`.
- При точной ошибке ЕСМ `1013` или сетевом сбое массовая операция повторяет запрос до трех раз с паузой.
- Аварийный PowerShell-сценарий проверяет диапазон портов, экранирует подстановки и запускается только после валидации данных подключаемой ККТ.
- Первая ККТ защищена от удаления. Защита снимается только для дополнительных строк, когда ровно один экземпляр имеет `port = 50401` или `softPort = 0`.
- Удаление требует последние четыре цифры серийного номера, повторно проверяет список перед `DELETE` и подтверждает исчезновение экземпляра повторными `GET`.
- Полный журнал сохраняется в `%LOCALAPPDATA%\EsmTspiotTool\Logs`; файлы старше 14 дней удаляются.
- Экранный журнал ограничен по размеру; после обрезки полная история остается в файловом журнале. Закрытие формы во время операции не вызывает обращений к уничтоженным элементам UI.
- Кнопка `Скопировать диагностику` маскирует ИНН, номера ККТ, ФН, локальные пути профиля Windows и типовые секреты в диагностическом JSON. Само поле журнала остается редактируемым.

## Ручной сценарий

1. Проверить соединение в верхней строке.
2. На вкладке `Ручное подключение` нажать `Выбрать следующую ККТ`.
3. Если найдено несколько новых физических ККТ, явно выбрать нужную по серийному номеру, ФН и ИНН.
4. Проверить автоматически подставленную свободную пару портов.
5. Закрыть Frontol и добавить экземпляр.
6. В драйвере АТОЛ выбрать подключаемую физическую ККТ и проверить связь.
7. Установить флажок подтверждения.
8. Зарегистрировать ККТ.
9. Убедиться, что нижняя таблица обновилась, и повторить шаги для следующей кассы.

## Экспериментальный массовый сценарий

Кнопка `Запустить автоматический режим` на отдельной вкладке сначала только собирает данные и показывает план. До нажатия `Начать регистрацию` изменяющих запросов нет.

- Уже полностью зарегистрированные ККТ пропускаются.
- Незавершенный существующий экземпляр может быть продолжен без повторного `POST`.
- Новым ККТ назначаются свободные пары `50402/51402`, `50403/51403` и далее. Пара первой ККТ `50401/51401` дополнительным экземплярам не выдаётся.
- Дубли в ответе ДККТ пропускаются.
- Некорректные данные блокируют только соответствующую строку.
- Некорректная строка плана не расходует назначаемую пару портов.
- Автоматический PowerShell и автоматическое создание служб не выполняются.

## Удаление дополнительного экземпляра

На вкладке `ККТ в ЕСМ` отображается таблица экземпляров. Первая ККТ помечается как защищенная. После выбора дополнительной строки доступна команда удаления с подтверждением последних четырех цифр серийного номера.

Если первая ККТ не определяется однозначно, удаление блокируется для всех строк. Успех фиксируется только после повторного `GET /api/v1/instances/info`, в котором удаленный `id` отсутствует.

## Контроллеры ЛМ ЧЗ для ККТ с разными ИНН

Вкладка `Контроллеры ЛМ ЧЗ` объединяет зарегистрированные ККТ, их порты ЕСМ, Windows-службы контроллеров и привязку к ЕСМ.

1. Получите `esm-lm-controller_*-windows-setup.exe` из легальной поставки ПИоТ. Нажмите `Выбрать…`, проверьте версию, подписанта и SHA-256, затем нажмите `Установить / проверить версию`. Установщик не входит в релиз.
2. Нажмите `Обновить`. Таблица покажет ККТ, ИНН, состояние и порты ЕСМ, роль/имя службы, gRPC/REST, целевой ЛМ и результат привязки текущего сеанса.
3. Для каждой строки введите адрес и порт её целевого ЛМ, логин и пароль. Локальный адрес фиксирован как `127.0.0.1`; свободные gRPC/REST-порты программа предлагает последовательно.
4. Нажмите `Подготовить план`, затем `Создать / обновить выбранные`. После одного UAC helper последовательно подготовит изолированные профили, службы и порты. Затем программа проверит готовность и последовательно вызовет `PUT /api/v1/settings/lm/{id}`.
5. Если служба готова, а привязка не удалась, используйте `Повторить привязку к ЕСМ`: служба не пересоздаётся и UAC не запрашивается.
6. `Удалить службу` работает только для одной выбранной управляемой службы и требует полный 14-значный номер ККТ. Локальные данные удаляются автоматически, но привязка в ЕСМ не очищается. При `CleanupPending` используйте `Повторить очистку`.

Обычный `PUT /api/v1/settings/{id}` не используется. Специализированный `PUT /api/v1/settings/lm/{id}` вызывается только после валидации, подтверждения плана и проверки готовности контроллера. Документированного read-back этой настройки у ЕСМ нет, поэтому ответ 2xx называется `Запрос принят`, а не `Проверено`.

## Типовые ошибки

- `1010` - экземпляр с таким `id` уже существует.
- `1012` - служба с таким именем не создана. В ручном режиме утилита подготавливает диагностический PowerShell-сценарий создания службы.
- `1013` - служба не запущена. В ручном режиме доступен сценарий восстановления; массовый режим делает ограниченные повторы.
- `1015` - не запущена служба ДККТ АТОЛ или неверен `dkktPort`.
- `2046` - экземпляр ЕСМ не зарегистрирован или не запущен.
- `403` - проверить регистрацию, сертификаты, права и состояние ЕСМ.

## Сборка

Legacy в Visual Studio 2022:

```powershell
msbuild .\src\EsmTspiot.Legacy.WinForms\EsmTspiot.Legacy.WinForms.csproj /p:Configuration=Release
```

Modern x64 self-contained:

```powershell
dotnet publish .\src\EsmTspiot.Modern.WinForms\EsmTspiot.Modern.WinForms.csproj -c Release -r win-x64 --self-contained true
```

Modern x86 self-contained:

```powershell
dotnet publish .\src\EsmTspiot.Modern.WinForms\EsmTspiot.Modern.WinForms.csproj -c Release -r win-x86 --self-contained true
```

Тесты:

```powershell
dotnet run --project .\tests\EsmTspiot.Shared.Tests\EsmTspiot.Shared.Tests.csproj
```

Отдельно запускаются 60 тестов привилегированного helper. Shared-раннер содержит 121 сценарий и прогоняется в .NET 8 и .NET Framework. Workflow `.github/workflows/ci.yml` также собирает Legacy, Modern и helper, запускает LM safety gate и проверяет состав компактного ZIP.

Компактная поставка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package_compact_release.ps1
```

На машине без .NET SDK shared-тесты и Legacy EXE можно собрать системным `csc.exe`; используемые команды зафиксированы в истории разработки.
