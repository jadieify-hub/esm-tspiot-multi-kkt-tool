# Мульти-ККТ в ЕСМ/ТС ПИоТ

[![CI](https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/actions/workflows/ci.yml/badge.svg)](https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/actions/workflows/ci.yml)

WinForms-приложение работает с локальным HTTP API ЕСМ/ТС ПИоТ. Оно показывает созданные экземпляры и занятые порты, последовательно подключает одну или несколько ККТ, содержит массовый режим и безопасное удаление выбранного экземпляра с усиленным подтверждением для первой ККТ. Полный автоматический режим регистрирует все ККТ независимо, а затем по отдельному подтверждению создаёт для каждой ККТ прямую службу официального контроллера ЛМ, по выбранному оператором официальному MSI устанавливает по одному независимому ЛМ ЧЗ на каждый ИНН с автозапуском, привязывает контроллеры в ЕСМ и сверяет результат контрольным чтением ЕСМ. Бизнес-инициализацию ЛМ программа не выполняет: её делает ЕСМ при работе или оператор.

Программа не меняет настройки драйвера АТОЛ. В ручном сценарии пользователь обязан проверить связь именно с нужной физической ККТ.

## Готовые версии

Локальная сборка складывает итоговые файлы в игнорируемую Git папку `artifacts/release`. Опубликованные версии доступны в [GitHub Releases](https://github.com/jadieify-hub/esm-tspiot-multi-kkt-tool/releases/latest). Стандартный ассет:

- `MultiKKT-ESM-TSPioT-compact.zip` — Legacy-приложение, его DLL и привилегированный helper; нужен .NET Framework 4.8.

Для управления Windows-службами архив распаковывает администратор в `C:\Program Files\KRS\MultiKKT`. Из Downloads, Desktop и других доступных на запись папок создание, обновление и удаление служб намеренно отключено; чтение состояния и обычные операции с ЕСМ остаются доступными.

Автономные Modern-сборки размером около 60 МБ в стандартный релиз не входят и готовятся только по явному запросу. Вендорные бинарники в архив не входят. Для настройки контроллеров на машине должен быть штатно установлен официальный `ЕСП Контроллер ЛМ ЧЗ` версии `1.6.4.0`; программа находит и проверяет установленный `lmcontroller.exe`, но не копирует его в поставку. Официальный MSI ЛМ ЧЗ `regime-2.6.1-7.msi` оператор указывает сам кнопкой `Выбрать MSI...` на вкладке `ЛМ ЧЗ`; в поставку он не входит и сверяется со встроенным профилем.

## Реализованные запросы ЕСМ

- `GET /api/v1/instances/info` - список экземпляров.
- `GET /api/v1/instances/info/{id}` - подробности экземпляра и `regData`.
- `GET /api/v1/dkktList` - физические ККТ, доступные через ДККТ.
- `POST /api/v1/tspiot` - добавление экземпляра.
- `PUT /api/v1/tspiot` - регистрация ККТ.
- `DELETE /api/v1/tspiot/{id}` - удаление дополнительного экземпляра.
- `GET /api/v1/settings/{id}` - чтение конфигурации для диагностики.
- `PUT /api/v1/settings/lm/{id}` - привязка зарегистрированной ККТ к готовому контроллеру ЛМ ЧЗ.

`PUT /api/v1/settings/{id}` намеренно не вызывается: автоматическая перезапись неизвестной конфигурации слишком рискованна.

## Надежность и безопасность

- Ответы `/instances/info` и `/dkktList` проверяются по ожидаемой JSON-структуре. При неожиданном ответе изменяющие запросы не выполняются.
- ИНН проверяется по длине, ASCII-цифрам и контрольным цифрам.
- Серийный номер ККТ должен содержать 14 ASCII-цифр, ФН - 16 ASCII-цифр.
- Нетипичные префиксы ККТ и ФН дают предупреждение, но не блокируют работу.
- Порты проверяются на диапазон и различие, включая запрет совпадения `port` или `softPort` с `dkktPort`.
- Значение `dkktPort` по умолчанию — `4042` (порт оркестра ДККТ для ЕСМ). Порт `4041` относится к службе АТОЛ для ККМ и не подставляется в запросы ЕСМ по умолчанию.
- В ручном режиме отображаются все созданные экземпляры ЕСМ и занятые ими порты. Свободная пара рассчитывается по фактическому списку; одна занятая сторона резервирует всю пару.
- Адрес не на loopback-интерфейсе вызывает предупреждение перед продолжением.
- Массовая операция выполняет устройства последовательно, продолжает работу после ошибки одной ККТ и поддерживает остановку с сохранением уже полученных результатов.
- Регистрация, контроллеры и ЛМ ЧЗ — независимые фазы: ошибка контроллера или ЛМ не откатывает уже зарегистрированную ККТ и не мешает регистрации остальных касс; итог «контур настроен» выдаётся только после подтверждения привязки контрольным чтением ЕСМ.
- ЛМ ЧЗ устанавливаются только из официального MSI, совпавшего со встроенным профилем по SHA-256 и структуре; клоны получают собственные ProductCode, каталог, службы, cookie и правило firewall на один порт API. Программа передаёт пакету только известные ему свойства (`ADMINUSER`, `ADMINPASSWORD`, `AUTOSERVICE`, `APPLICATIONFOLDER`), не журналирует командную строку `msiexec` и не читает пароли обратно.
- Базовый ЛМ вендора не переустанавливается: программа лишь включает его службам автозапуск, записывает прежний режим в manifest и возвращает его при удалении или откате.
- Перед подтверждением и UAC программа одним снимком проверяет все новые локальные порты. Порты уже принадлежащих существующим комплектам повторно проверяются привилегированным helper по manifest, SCM, процессам и listeners.
- Привилегированный helper не принимает произвольные команды, пути, аргументы или секреты; имена служб, профили и пути выводятся только из проверенных серийных номеров и ИНН.
- Поддержка контроллера привязана к проверенному capability-профилю версии `1.6.4.0`: точным размеру и SHA-256 бинарника, Amd64, подписи JSC ESP и установленному продукту. Другая версия не запускается «наугад».
- Первая ККТ использует штатную службу `esm-lm-controller`; дополнительные ККТ получают прямые SCM-клоны того же проверенного вендорного бинарника. Постоянных KRS-supervisor, Provisioner, Erlang runtime или прокси-служб новая схема не создаёт.
- Для клонов создаются только изолированные конфигурации и сертификаты. Общий доверенный CA берётся из проверенного штатного профиля; `server.*` генерируются самим контроллером отдельно для каждого клона.
- Удаляются только объекты с полностью подтверждённой меткой владения KRS. Службы, профили, данные, журналы и метаданные очищаются автоматически; при `CleanupPending` есть кнопка `Завершить очистку`.
- При точной ошибке ЕСМ `1013` или сетевом сбое массовая операция повторяет запрос до трех раз с паузой.
- Аварийный PowerShell-сценарий проверяет диапазон портов, экранирует подстановки и запускается только после валидации данных подключаемой ККТ.
- Первая ККТ удаляется только с усиленным подтверждением: оператор вводит весь 14-значный серийный номер. Для дополнительных ККТ достаточно последних четырёх цифр.
- Удаление повторно проверяет список перед `DELETE` и подтверждает исчезновение экземпляра повторными `GET`. Если первая ККТ не определяется однозначно, изменение блокируется.
- Полный журнал сохраняется в `%LOCALAPPDATA%\EsmTspiotTool\Logs`; файлы старше 14 дней удаляются.
- Экранный журнал ограничен по размеру; после обрезки полная история остается в файловом журнале. Закрытие формы во время операции не вызывает обращений к уничтоженным элементам UI.
- Кнопка `Скопировать диагностику` маскирует ИНН, номера ККТ, ФН, локальные пути профиля Windows и типовые секреты в диагностическом JSON. Само поле журнала остается редактируемым.

## Ручной сценарий

1. Проверить соединение в верхней строке.
2. На вкладке `Ручное подключение` нажать `Выбрать следующую ККТ`.
3. Если найдено несколько новых физических ККТ, явно выбрать нужную по серийному номеру, ФН и ИНН.
4. Проверить автоматически подставленную свободную пару портов.
5. Закрыть Frontol и добавить экземпляр.
6. В драйвере АТОЛ выбрать подключаемую физическую ККТ и проверить связь.
7. Установить флажок подтверждения.
8. Зарегистрировать ККТ.
9. Убедиться, что нижняя таблица обновилась, и повторить шаги для следующей кассы.

## Полный автоматический сценарий

На первой вкладке `Автоматическая настройка` нажмите `Зарегистрировать и настроить`. MSI ЛМ ЧЗ можно выбрать заранее на вкладке `ЛМ ЧЗ` или в диалоге следующей фазы. Сначала программа завершит регистрацию ККТ. Затем она отдельно спросит «Настроить независимые контроллеры и ЛМ ЧЗ сейчас?» и предупредит, что фаза кратковременно перезапустит соответствующие экземпляры ЕСМ: её можно выполнить сейчас или отложить без отката регистрации.

Дальше программа для каждой строки по очереди:

1. добавляет и регистрирует ККТ в ЕСМ, если это ещё не сделано;
2. после отдельного согласия проверяет установленный официальный контроллер `1.6.4.0`;
3. оставляет первую ККТ на штатной службе и создаёт прямые службы-клоны для остальных ККТ;
4. назначает gRPC/REST-порты `50063/5063`, `50064/5064` и далее;
5. точечно обновляет только `settings.ldbControl` в `config_<serial>.yml` и последовательно перезапускает экземпляры ЕСМ;
6. по официальному MSI устанавливает один ЛМ ЧЗ на каждый ИНН: первый ИНН получает базовый `regime`/`yenisei` (API `5995`, CouchDB `5984`), следующие — клоны `regime1`/`yenisei1` (`6995`/`7984`) и далее с шагом `1000`; службам включается автозапуск, у предсуществующего базового ЛМ прежний режим запуска записывается в manifest;
7. привязывает контроллеры через API ЕСМ и затем читает `/api/v2/info` каждой ККТ, сверяя адрес и порт привязки с планом;
8. показывает построчный итог: регистрация, контроллеры, ЛМ по ИНН, ответ ЕСМ по ККТ. Ответ ЕСМ `2025`/`2055` означает, что ЛМ установлен и привязан, но ещё не инициализирован; контур это не ломает.

Регистрация в ЕСМ выполняется в одном из двух режимов, программа выбирает его сама:

- если драйвер уже держит связь с кассами одного ИНН, используется обычный режим по текущим сессиям драйвера;
- если сессий драйвера нет совсем или среди касс есть разные ИНН с незавершённой регистрацией, включается поочерёдный режим VCOM: программа находит USB-порты касс АТОЛ, через установленный `Драйвер ККТ v.10` подключает кассы строго по одной, регистрирует каждую и закрывает связь, а в конце снова подключает все кассы и проверяет, что ЕСМ видит полный список.

Для поочерёдного режима нужен установленный `Драйвер ККТ v.10` (АТОЛ ДТО 10) и свободные кассы. Если связь с кассами удерживает Frontol или `Тест драйвера ККТ`, программа попросит закрыть их и повторить; чужие программы она не завершает сама.

- Полный сценарий повторно выбирает все зарегистрированные ККТ: снятая ранее галочка на ручной вкладке не может незаметно исключить кассу.
- Уже полностью зарегистрированные ККТ пропускаются.
- Незавершенный существующий экземпляр может быть продолжен без повторного `POST`.
- Новым ККТ назначается первая свободная пара, начиная с `50401/51401`. Если ЕСМ уже возвращает первую ККТ с `port=50401` или `softPort=0`, эта пара считается занятой и следующая ККТ получает `50402/51402`.
- Дубли в ответе ДККТ пропускаются.
- Некорректные данные блокируют только соответствующую строку.
- Некорректная строка плана не расходует назначаемую пару портов.
- Кнопка `Остановить` прекращает сценарий после текущей безопасной операции; уже зарегистрированные ККТ и созданные службы не откатываются.
- Сбой одной ККТ в фазе контроллеров не превращает остальные строки в отменённые: каждая служба обрабатывается независимо.
- Итог «контур настроен» означает: контроллеры запущены, ЛМ ЧЗ установлены с автозапуском, привязка передана ЕСМ и подтверждена контрольным чтением. Отложенная оператором установка ЛМ или неподтверждённая привязка дают честный частичный итог с названной причиной. Инициализацию ЛМ программа не выполняет и не ждёт.
- Учётные данные привязки передаются только в запросе ЕСМ и не сохраняются в профиле, manifest или журнале.

## Удаление экземпляра ККТ

На вкладке `ККТ в ЕСМ` отображается таблица экземпляров. После выбора строки доступна команда удаления. Для первой или единственной ККТ требуется ввести полный 14-значный серийный номер; для дополнительной — последние четыре цифры.

Если первая ККТ не определяется однозначно, удаление блокируется для всех строк. Успех фиксируется только после повторного `GET /api/v1/instances/info`, в котором удаленный `id` отсутствует.

## Контроллеры и ЛМ ЧЗ для нескольких ККТ

Вкладка `ЛМ ЧЗ` управляет прямыми контроллерами и независимыми ЛМ ЧЗ: по одному контроллеру на ККТ и по одному ЛМ на ИНН.

1. Штатно установите официальный `ЕСП Контроллер ЛМ ЧЗ 1.6.4.0`; официальный MSI ЛМ ЧЗ `regime-2.6.1-7.msi` держите под рукой.
2. Нажмите `Обновить`, чтобы увидеть зарегистрированные ККТ, назначения контроллеров и установленные ЛМ.
3. Нажмите `Выбрать MSI...` и укажите MSI ЛМ. Программа сверяет его SHA-256 и структуру таблиц со встроенным профилем и отказывает неизвестному пакету до запуска `msiexec`.
4. Нажмите `Настроить контроллеры и ЛМ ЧЗ`. Первая ККТ использует `esm-lm-controller`; дополнительные — `esm-lm-controller-2`, `-3` и далее. Если ожидаемое имя занято чужой службой, программа выбирает следующий свободный ordinal, а не усыновляет её.
5. Для ordinal 1 используются gRPC `50063`, REST `5063`; для ordinal 2 — `50064`, `5064`; далее порты растут последовательно. Контроллер каждой ККТ указывает на ЛМ её ИНН: `127.0.0.1:5995` для первого ИНН, `127.0.0.1:6995` для второго и далее.
6. ЛМ ЧЗ ставятся из MSI с вендорными свойствами `ADMINUSER`/`ADMINPASSWORD` (`admin/admin`, те же, что в привязке ЕСМ) и `AUTOSERVICE=1`, поэтому клоны сразу получают автозапуск и стартуют самим пакетом. Базовый ЛМ, установленный вендором, только усыновляется: ему включается автозапуск, а прежний режим записывается в manifest и возвращается при удалении. Клоны — перепакованные копии того же MSI с собственными ProductCode, каталогом, службами `regimeN`/`yeniseiN`, cookie и правилом firewall только на порт API.
7. При отсутствии `config_<serial>.yml` операция ждёт появления файла ограниченное время и честно сообщает об отсрочке. `config-orchestrator.yml` программа не меняет.
8. Кнопка `Удалить всё созданное` удаляет только подтверждённые клоны KRS: ЛМ-клоны с их правилами firewall и manifest, затем контроллеры с восстановлением экземплярных YAML при совпадении применённого хэша. Штатная служба `esm-lm-controller` и базовый ЛМ сохраняются, базовому возвращается прежний режим запуска. Чужие службы и изменённые после настройки файлы не трогаются. Привязку ККТ в ЕСМ программа не удаляет и предупреждает об этом.

Ручной режим — те же стадии по отдельности, под кнопкой автомата: `Шаг 1: контроллеры`, `Шаг 2: ЛМ ЧЗ`, `Шаг 3: привязка к ЕСМ`, `Шаг 4: проверить по ЕСМ`. Каждый шаг сначала перечитывает ЕСМ и безопасен при повторе; шаги 1–3 требуют helper и UAC, шаг 4 только читает `/api/v2/info` и обходится без UAC.

После операции постоянными остаются только вендорные процессы: `lmcontroller.exe` по одному на службу контроллера и дерево Erlang (`erl`, `epmd`, `inet_gethost` и другие) по одному на каждый ЛМ. Helper запускается разово под UAC и завершается. Процессы `KRS LM Service Provisioner`, собственный Erlang/EPMD/inet_gethost и supervisor новой схемой не создаются.

## Типовые ошибки

- `1010` - экземпляр с таким `id` уже существует.
- `1012` - служба с таким именем не создана. В ручном режиме утилита подготавливает диагностический PowerShell-сценарий создания службы.
- `1013` - служба не запущена. В ручном режиме доступен сценарий восстановления; массовый режим делает ограниченные повторы.
- `1015` - не запущена цепочка служб ДККТ/оркестра или неверен `dkktPort` (обычно `4042`).
- `1026` - ЕСМ обнаружила кассы разных ИНН и отказалась выполнять регистрацию; это ограничение/состояние ЕСМ, а не ошибка локального контроллера. Обход: оставить в драйвере связь только с кассами одного ИНН или запустить полный автоматический сценарий — он поочерёдно подключит и зарегистрирует кассы через VCOM.
- `2025`/`2055` - ЕСМ сообщает, что ЛМ ЧЗ не инициализирован. После настройки контура это ожидаемое состояние: ЛМ установлен и привязан, инициализацию выполняет ЕСМ или оператор.
- `2046` - экземпляр ЕСМ не зарегистрирован или не запущен.
- `403` - проверить регистрацию, сертификаты, права и состояние ЕСМ.

## Сборка

Legacy в Visual Studio 2022:

```powershell
msbuild .\src\EsmTspiot.Legacy.WinForms\EsmTspiot.Legacy.WinForms.csproj /p:Configuration=Release /p:LangVersion=5
```

Modern x64 self-contained:

```powershell
dotnet publish .\src\EsmTspiot.Modern.WinForms\EsmTspiot.Modern.WinForms.csproj -c Release -r win-x64 --self-contained true
```

Modern x86 self-contained:

```powershell
dotnet publish .\src\EsmTspiot.Modern.WinForms\EsmTspiot.Modern.WinForms.csproj -c Release -r win-x86 --self-contained true
```

Тесты:

```powershell
dotnet run --project .\tests\EsmTspiot.Shared.Tests\EsmTspiot.Shared.Tests.csproj
```

Точная численность тестов выводится release-матрицей и растёт вместе с проектом. Workflow `.github/workflows/ci.yml` собирает общий код и операторские тесты для net8/net48, Legacy и helper строго в режиме C# 5, проверяет интерфейс, Modern, LM safety gate и состав/main-helper-контракт компактного ZIP.

Компактная поставка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package_compact_release.ps1
```

На машине без .NET SDK shared-тесты и Legacy EXE можно собрать системным `csc.exe`; используемые команды зафиксированы в истории разработки.
